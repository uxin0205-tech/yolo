## 七、RepConv 研究文件摘錄（2026-08-31，含文件內 2026-09-02 更正）

- **RC-01（sites／選位）**：研究文件把第一輪 RepConv sites 定義為 outer stride-2 transition：layer 17（P3→P4、`Conv[256,3,2]`）與 layer 20（P4→P5、`Conv[512,3,2]`）；layer 16、19、22 不動。研究明列這是工程推論／待驗證假說，不是文獻已證明 P3/P4 必勝；不是全面替換 C3k2 或其內所有 `3×3`。（來源：[研究#L18-L20](<../../docs/research/2026-08-31-repconv-binaryqk.md#L18-L20>)、[研究#L83-L91](<../../docs/research/2026-08-31-repconv-binaryqk.md#L83-L91>)、[研究#L214-L240](<../../docs/research/2026-08-31-repconv-binaryqk.md#L214-L240>)）
- **RC-02（RepConv parent／先後）**：研究建議從現行 Full35 J3 `best_joint` 未 fuse parent 出發，固定 MASF／BinaryQK；先做 function-preserving graft、訓練、fuse，再重建 deployment catalog/calibration 與 matched PTQ。研究的立即決策也要求 RepConv 與 MASF/BinaryQK 先獨立，最後才做 interaction；RepConv fuse 後才進量化 gate。（來源：[研究#L71-L73](<../../docs/research/2026-08-31-repconv-binaryqk.md#L71-L73>)、[研究#L104-L121](<../../docs/research/2026-08-31-repconv-binaryqk.md#L104-L121>)、[研究#L468-L474](<../../docs/research/2026-08-31-repconv-binaryqk.md#L468-L474>)）
- **RC-03（最小矩陣 arms）**：`R0`＝layer17 Conv、layer20 Conv；`R1`＝17 RepConvN／20 Conv；`R2`＝17 Conv／20 RepConvN；`R3`＝17+20 RepConvN，其他結構均 Full35 J3 且 MASF/BinaryQK 固定。先解析 runtime module path/shape、同一 parent graft、等價測試，再以同 loader/recipe、每組至少 3 seeds 訓練，validation 選擇、test freeze 後一次評估，並做 pre/post-fuse 與實際 backend p50/p95。（來源：[研究#L370-L385](<../../docs/research/2026-08-31-repconv-binaryqk.md#L370-L385>)）
- **RC-04（數值等價結論）**：本機 `RepConv` training graph 是 `3×3 ConvBN + 1×1 ConvBN + optional identity BN`，`get_equivalent_kernel_bias()`／`fuse_convs()` 可融合成單一 `3×3`；identity 只在 channel 相同且 stride=1 存在，故 stride=2 的 layer17/20 無 identity。CPU audit 把原 Conv/BN 搬到 3×3 branch、將 1×1 branch BN gamma/beta 歸零後，graft 初始輸出 `max_abs=0`；fuse 後相對原 Conv `max_abs=1.073e-6`，通過工程 `≤1e-5` gate。訓練期 layer17/20 各增 66,048／263,168 parameters（合計 329,216），融合後消失，deploy 仍是原 shape 單一 `3×3 Conv+bias`，所以沒有相對原 Conv 的部署 MAC 降低。（來源：[研究#L95-L121](<../../docs/research/2026-08-31-repconv-binaryqk.md#L95-L121>)、[研究#L218-L222](<../../docs/research/2026-08-31-repconv-binaryqk.md#L218-L222>)）
- **RC-05（必要 post-fuse gate）**：RepConv 的 FP32 融合等價不代表 INT8 等價；研究引用 QARepVGG 的量化風險，要求先 fuse、過 FP32 parity 與完整八指標，再重建 fused deployment catalog，observer/calibration 看 fused weights/activations，做 accepted SiLU/qSiLU matched PTQ；若只有量化失敗，才另評估 QARepVGG/RepOptimizer。每候選還要報 fused/export params、GFLOPs、checkpoint size、target p50/p95、throughput、peak memory 及 graft/fuse 前後 `max_abs`/`mean_abs`。（來源：[研究#L242-L254](<../../docs/research/2026-08-31-repconv-binaryqk.md#L242-L254>)、[研究#L451-L464](<../../docs/research/2026-08-31-repconv-binaryqk.md#L451-L464>)）
- **RC-06（停止／交互）**：若 R1/R2/R3 都沒有 paired-seed CI 的 accuracy 改善或非劣，且 fused latency 相對 R0 無可重複改善，就不擴大到 C3k2 內部／全 Neck；只有 R1 有效時只保留 layer17。RepConv winner 與 current/recovered BinaryQK 的 interaction 另做同一 Full35 J3 lineage `I0…I3` 2×2，MASF 四格固定；研究總結仍要求 accuracy／post-fuse PTQ 不可接受時停止擴大。（來源：[研究#L387-L387](<../../docs/research/2026-08-31-repconv-binaryqk.md#L387-L387>)、[研究#L423-L430](<../../docs/research/2026-08-31-repconv-binaryqk.md#L423-L430>)、[研究#L512-L518](<../../docs/research/2026-08-31-repconv-binaryqk.md#L512-L518>)）
