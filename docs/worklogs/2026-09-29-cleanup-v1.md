# 2026-09-29：建立 Cleanup-v1 程式與報告基線

## 任務與範圍

依使用者要求清理 YOLO，排除 checkpoint 等大型產物，保留基本程式碼與報告，建立 `Cleanup-v1` 供後續更新。此次發行以 GitHub `main` 的 `1d409c4fe21d3287d6f19be48f4457407a6bb50e` 為來源；本機 `main` 已分歧且含未提交檔案，故使用獨立工作樹準備，不混入其他研究修改。

`main` 要刪除分支或只清理內容、本機權重是否也要永久刪除，已向使用者詢問。這兩項決定尚未取得時，本次只發布新分支；本機原始資料與權重、GitHub `main` 及其他舊分支均未刪除。

## 變更內容與原因

- 新分支採無 parent 的 root commit，避免繼承 checkpoint、資料集與巨型日誌的舊歷史；來源 SHA 和完整排除清單保留於 `docs/cleanup-v1/`。
- 來源共 114,933 個檔案，保留原有 7,750 個，排除 107,183 個。全部 1,495 個既有 Python 檔與 937 個 YAML 保留；沒有修改模型、訓練或評估演算法。
- 排除 226 個模型／checkpoint／分片權重、106,352 個資料集本體／symlink、80 個執行期產物、92 個逐筆預測、6 個大型逐步訓練 CSV／JSONL、427 張 batch 預覽。
- 保留 Markdown／PDF 報告、統計圖表、摘要 CSV／JSON、設定、split 與 lineage。56 張 LFS 報告圖片從本機 cache 還原為一般 Git 檔案，每張核對 SHA-256，圖片內容不改寫。
- 檔案邏輯總量從 20,636,965,087 bytes 降到原有保留項目 842,673,721 bytes，減少約 95.92%；另加入約 20 MB 的排除清單與少量文件／工具。此數值包含各路徑的 LFS 實體大小，不等於 GitHub 計費、Git pack 大小或已回收空間。
- 移除所有 LFS tracking 與歷史權重納入例外；保留 CSV／SVG 的原始 byte 屬性。根層與各子專案忽略規則一致排除模型、分片、資料本體與執行期垃圾。
- 新增標準函式庫維護工具 `tools/check_repository_hygiene.py` 及 GitHub Actions；檢查暫存區內禁止的產物、LFS 指標及 25 MiB 單檔上限。
- 根 README、資料集規範與受影響 README 說明 Cleanup-v1 的發行邊界。歷史 manifest、checksum 與數值仍作研究證據，完整驗證／推論／續訓需要另外提供原資產。

## 驗證方式與結果

- 發布前透過 SSH fetch 確認遠端來源 SHA 與盤點相同。
- 對 7,750 個保留來源逐一確認存在；未刻意修改的檔案逐一核對 Git blob SHA，56 張 LFS 圖片核對 SHA-256，失敗數 0。
- 使用 `ast.parse` 解析 1,496 個 Python 檔（1,495 個既有程式與 1 個新檢查工具），語法失敗數 0；這不是模型執行或精度驗證。
- 在獨立暫存 Git 儲存庫驗證 4 種情境：程式／報告通過；分片 checkpoint、LFS 指標、26 MiB 單檔均正確拒絕。
- `git check-ignore --no-index` 驗證全部 107,183 個排除路徑均被最終忽略規則擋下。
- 根 README／AGENTS 及新增文件連結檢查通過；根 README 保留資料集規範與工作紀錄入口。
- 最終暫存區檔案檢查通過：7,761 個檔案，約 0.863 GB，沒有模型、資料本體或 LFS 指標。Git whitespace 檢查按來源到新分支的實際新增／修改範圍執行並通過；發布結果另於本機工作紀錄補記。
- 未跑模型套件全測試、GPU、PTQ、QAT、訓練或精度評估：本次不改演算法，且移除發行資產後，完整模型驗證仍需外部權重與資料。

## 困難與解法

- 沙箱啟動受 `bwrap: loopback: Failed RTM_NEWADDR: Operation not permitted` 影響，透過工具權限審查後執行必要讀寫與連線操作。
- 系統沒有 `python` 命令，改用 `python3` 進行盤點與驗證。
- 新產生的 CSV 預設使用 CRLF，初次 Git whitespace 檢查失敗；只將本次排除清單轉為 LF，並修正兩份新改動 attributes 的尾端空白行。歷史 CSV 證據未改寫。
- 原工作區有大量未追蹤內容，本機 main 相對快取 origin/main 領先 1 個、落後 63 個提交；獨立工作樹只取 GitHub main 的授權內容，保留本機現況。
- 舊子目錄 `.gitignore` 有 checkpoint／完整資料 snapshot 例外，已移除權重例外並在各忽略檔末尾加入一致政策，防止根層規則被覆蓋。
- 本機 `gh` CLI 尚未登入；使用 GitHub 連接器讀取遠端資訊、既有 SSH 發布分支，不讀取或輸出憑證。

## 未解事項或風險

- GitHub main 目前是預設分支。若選擇刪除 main，須先變更新分支為預設；分支處置及本機刪除仍待前述範圍確認。
