# 1119 · 權重選型、形狀導讀與工作區清理

11 月 19 日收到選型與清理指示，作業跨至 11 月 20 日凌晨（Asia/Taipei）。使用者指定的 Git 提交名稱為 `1119`。

## 選型與變更原因

- 硬體版使用固定 H×W＝512×768 的獨立適應權重，在 10 輪適應段第 2 輪取得。以 Stage9 原 exporter 由該輪權重建立獨立可攜包。精度版取原本 qSiLU 訓練的 Rep17＋20 E1，使用原批次 rect640 前處理。兩個版本共用相同簡化算子。[兩份權重、十項 AP 及載入方式](../../result/README.md)
- 根層 README 依實際血緣列出九個步驟，每步說明問題、採用結果與下一個起點。依指定名稱新增 yolo_reshape 導讀，實驗仍在 yolo_actshape 的原位置。[研究順序](../../README.md) · [特徵圖研究](../../yolo_reshape/README.md)
- 第 9 階段當時的自動門檻、原始評估與 120 輪結果照錄。這次按部署用途指定兩個版本，AP 引用已完成的完整驗證，本次未開 GPU 或重跑訓練。

## 刪除範圍

刪除整個舊 yolo_optimize 目錄，刪前磁碟配置量為 **246,619,746,304 bytes（229.68 GiB）**，內含舊 archives、實驗、模型及報告。另刪除根層被取代的 README.md.orig 與 .gitignore.orig。刪除前確認未見使用該目錄的可見程序檔案控制代碼、目錄內掛載點或階段資料夾中直接指向它的符號連結。舊模型 E5 的 SHA 及 110 個階段參考來源已核對；僅另外保留 Stage1 成本公式程式與 718 bytes 的浮點統計輸入。[刪前指紋與原始路徑](../research/data/1119/reference-index.json)

## 驗證方式與結果

先移開整個舊整合目錄，再把兩份可攜包分別複製到工作區外，清空 PYTHONPATH、停用 CUDA，於獨立 Python 程序重載。兩個模型的 Detect／Pose 皆在兩種輸入大小逐張量符合固定 SHA，每種輸入各驗 24 個輸出。兩個載入器的 qSiLU／D1 契約均通過，刻意換上 SiLU 時均拒絕。硬體版另用原適應模型在 CPU 產生參考輸出。通過後永久清除舊目錄。12 個既有研究資料夾內所抽核的 6,108 個程式、設定與研究紀錄，清理前後的 SHA-256 全數一致。[驗證紀錄](../../result/validation-1119.json)

## 困難、解法與重現限制

舊成本工具及部分來源鎖使用當時 yolo_optimize 的固定路徑。退役後舊來源檢查會要求原檔，原 optimize E5 的專屬驗證器也需要已刪的舊權重。兩份現行模型使用各自的凍結 runtime。Stage1 成本若需追溯，可比對[原統計輸入](../research/data/1119/stage1-fp.json)與[計算程式](../research/data/1119/stage1-accounting.py)。若要重新執行歷史訓練，須先取得與當時來源鎖相符的檔案。

本機 main 與先前記錄的遠端 main 已分岔，工作樹含既有未提交研究。此次使用獨立 Git 暫存區與本機分支 `publish-1119` 整理研究快照。提交含各步驟程式、設定、報告、模型載入契約與小型圖表。原始影像、訓練及部署 checkpoint、虛擬環境、快取與私人簡報未納入。

11 月 19 日核對時，本機 origin 指定的 `uxin0205-tech/yolo` 由 SSH 回報 Repository not found，GitHub 連接器也回報 404。SSH 登入身分已確認為 uxin0205-tech。同帳號另有公開的 `yolo-cleanup-20261029`，其 main 存有獨立的歷史清單，發行目的地需與使用者核對。硬體尚未執行 RTL／HLS 或實板量測。
